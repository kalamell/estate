# Estate — การวิเคราะห์และแนวทางพัฒนา

> เอกสารนี้สรุปการวิเคราะห์ความต้องการ ทางเลือกด้านแพลตฟอร์ม (เว็บ vs แอปเดสก์ท็อป) และแผนพัฒนาระบบบริหารอสังหาริมทรัพย์ให้เช่า
> ข้อมูลมาจากความรู้ทั่วไปด้านธุรกิจห้องเช่าและเทคโนโลยี ณ ปี 2026 — ข้อกฎหมายและราคาบริการควรตรวจสอบกับแหล่งทางการอีกครั้งก่อนใช้งานจริง

## 1. ความต้องการหลัก

| กลุ่มงาน | รายละเอียด |
|---|---|
| ประเภททรัพย์ | หอพัก, อพาร์ทเมนต์, คอนโด, บ้านเช่า, ห้องพักรายวัน (Airbnb / Booking / Agoda) |
| ทำเล | ปักหมุดโครงการบนแผนที่ ดูหลายสาขาในจอเดียว |
| ห้องพัก | ผังห้องรายชั้น, สถานะ (ว่าง / จอง / มีผู้เช่า / ปิดปรับปรุง), มุมมอง 3D ทั้งอาคารและภายในห้อง |
| การจอง | สัญญารายเดือน + จองรายวัน, กันจองซ้ำช่วงวันที่, เงินมัดจำ (รับ / คืน / ริบ) |
| มิเตอร์ | ถ่ายรูปหน้าปัด → อ่านตัวเลข (OCR) → ตรวจสอบ → บันทึกพร้อมรูปเป็นหลักฐาน |
| การเงิน | ออกบิลรายเดือนอัตโนมัติ (ค่าเช่า + ไฟ + น้ำ), QR PromptPay, บันทึกการชำระ, ยอดค้าง |

## 2. เว็บ หรือ แอปเดสก์ท็อป (Mac / Windows)?

Rust ทำได้ทั้งสองแบบ: แอปเดสก์ท็อปใช้ **Tauri 2** ซึ่งห่อ UI เว็บชุดเดียวกันเป็นไฟล์ `.dmg` / `.msi` ขนาดเล็ก (~10 MB)

### เปรียบเทียบ

| เกณฑ์ | เว็บ (Cloud) + PWA | แอปเดสก์ท็อป (Tauri) อย่างเดียว |
|---|---|---|
| ผู้ใช้หลายคน (เจ้าของ, แอดมิน, แม่บ้าน, คนจดมิเตอร์) | ✅ ใช้พร้อมกันได้ทุกที่ | ❌ ข้อมูลอยู่ในเครื่องเดียว |
| **จดมิเตอร์หน้าห้องด้วยมือถือ** | ✅ เปิดกล้องมือถือได้ทันที | ❌ ต้องถ่ายแล้วโอนรูปเข้าคอม |
| ผู้เช่าดูบิล / สแกนจ่าย / แจ้งซ่อม | ✅ ส่งลิงก์ผ่าน LINE ได้ | ❌ ทำไม่ได้ |
| ซิงก์ปฏิทิน Airbnb / Booking (iCal), รับ webhook ชำระเงิน | ✅ เซิร์ฟเวอร์ออนไลน์ตลอด | ❌ ทำงานเฉพาะตอนเปิดเครื่อง |
| หลายสาขา / หลายจังหวัด | ✅ | ❌ |
| สำรองข้อมูล | ✅ รวมศูนย์ ตั้งเวลาได้ | ⚠️ เสี่ยงหายถ้าเครื่องเสีย |
| ใช้งานตอนเน็ตล่ม | ⚠️ ต้องทำ offline cache เพิ่ม | ✅ |
| ค่าใช้จ่าย | ค่า VPS (เริ่มราว 150–500 บาท/เดือน) | ไม่มีค่าเซิร์ฟเวอร์ แต่มีค่าใบรับรอง code signing (Apple Developer ~99 USD/ปี, Windows cert) |
| การอัปเดต | ✅ อัปเดตครั้งเดียว ทุกคนได้ทันที | ต้องทำระบบ auto-update |

### ข้อสรุปและคำแนะนำ

**เลือก Web-based เป็นหลัก + PWA บนมือถือ แล้วค่อยเพิ่มแอปเดสก์ท็อป (Tauri) เป็นทางเลือก**

เหตุผล: งานหลักของธุรกิจนี้ "เกิดขึ้นนอกโต๊ะทำงาน" — จดมิเตอร์หน้าห้อง เช็คอินแขก ผู้เช่าจ่ายเงินผ่านมือถือ และต้องซิงก์กับ OTA ตลอดเวลา ซึ่งแอปเดสก์ท็อปอย่างเดียวตอบโจทย์ไม่ได้

โค้ดใน repo นี้ออกแบบให้รองรับทั้งสองแบบแล้ว:

```
            ┌─────────────── estate (Rust library: src/lib.rs) ───────────────┐
            │  REST API (Axum) · Billing · PromptPay · SQLite/PostgreSQL       │
            └───────────────┬───────────────────────────────┬─────────────────┘
                            │                               │
             estate (binary: src/main.rs)        Tauri desktop app (Phase 2)
             รันบน VPS / Cloud                    เรียก estate::serve() ภายในแอป
                            │                               │
         ┌──────────────────┼──────────────┐                │
     เบราว์เซอร์ PC     มือถือ (PWA)     ผู้เช่า (ลิงก์ LINE)     หน้าต่าง Mac / Windows
```

- **โหมดคลาวด์ (แนะนำ):** ใช้ไบนารี `estate` บนเซิร์ฟเวอร์ ทุกอุปกรณ์เข้าผ่านเบราว์เซอร์ ติดตั้งลงหน้าจอมือถือเป็น PWA ได้ (มี `manifest.webmanifest` แล้ว)
- **โหมดเดสก์ท็อป:** แอป Tauri ฝัง `estate::serve()` ไว้ในตัว ใช้ SQLite ในเครื่อง เหมาะกับหอพักเล็กที่มีแอดมินคนเดียวและไม่อยากเช่าเซิร์ฟเวอร์ (และถ้าต้องการเปิดให้มือถือในวง LAN เดียวกันเข้ามาจดมิเตอร์ได้ ก็ทำได้)

## 3. เทคโนโลยีที่เลือก

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| Backend | Rust + **Axum** + Tokio | เร็ว ใช้ RAM น้อย รันบน VPS ราคาถูกได้สบาย ปลอดภัยด้าน memory |
| ฐานข้อมูล | **SQLite** (SQLx) → ย้ายไป PostgreSQL ได้ | เริ่มง่าย ไฟล์เดียว เหมาะกับเดสก์ท็อป; เมื่อหลายสาขาค่อยเปลี่ยนเป็น Postgres |
| UI | HTML + Tailwind + Alpine.js | สวย เบา ไม่ต้อง build step; ใช้ซ้ำใน Tauri ได้ทันที |
| แผนที่ | Leaflet + OpenStreetMap | ฟรี ไม่ต้องใช้ API key (production ควรใช้ tile provider ที่รองรับปริมาณสูง) |
| 3D | Three.js | มุมมองอาคารรายชั้น (คลิกเลือกห้องได้) + มุมมองในห้องพร้อมจัดวางเฟอร์นิเจอร์ |
| OCR มิเตอร์ | Tesseract.js (ฝั่งเบราว์เซอร์) + ปรับภาพขาวดำ | ไม่เสียค่า API; ผู้ใช้ยืนยันตัวเลขก่อนบันทึกเสมอ |
| ชำระเงิน | PromptPay QR (EMVCo) เขียนเองใน Rust | ไม่มีค่าธรรมเนียม มี unit test ตรวจ CRC |
| เดสก์ท็อป | **Tauri 2** (Phase 2) | ใช้ Rust ทั้งระบบ ไฟล์เล็กกว่า Electron มาก |

ทางเลือกที่พิจารณาแล้วยังไม่ใช้: **Leptos/Dioxus** (UI เขียนด้วย Rust ล้วน) — ทำได้ แต่ทีมจะพัฒนา UI ช้ากว่า และ ecosystem ด้านแผนที่/3D ยังต้องเรียก JS อยู่ดี

## 4. ข้อควรรู้เฉพาะประเทศไทย

- **กฎหมายควบคุมสัญญาเช่าที่อยู่อาศัย (สคบ. พ.ศ. 2561)** ใช้กับผู้ให้เช่าตั้งแต่ 5 ห้องขึ้นไป โดยสาระสำคัญคือ เงินประกันรวมค่าเช่าล่วงหน้าไม่เกิน 3 เดือน, คืนเงินประกันภายใน 7 วันหลังสิ้นสุดสัญญา และค่าไฟ/ค่าน้ำต้องไม่เกินอัตราที่การไฟฟ้า/การประปาเรียกเก็บจริง → ระบบให้ตั้งอัตราต่อหน่วยรายโครงการได้ (ค่าตัวอย่าง 8/18 บาทเป็นแค่ demo) *ควรตรวจสอบประกาศฉบับล่าสุด*
- **PDPA:** ข้อมูลบัตรประชาชนผู้เช่าเป็นข้อมูลส่วนบุคคล ต้องมีระบบสิทธิ์ผู้ใช้ เข้ารหัส backup และนโยบายการเก็บรักษา (อยู่ใน Phase 2)
- **LINE** คือช่องทางหลักที่ผู้เช่าไทยใช้ → ส่งบิล / แจ้งเตือนค้างชำระผ่าน LINE Official Account
- **ห้องพักรายวัน:** การให้เช่ารายวันในคอนโดหรืออาคารบางประเภทอาจขัดกับ พ.ร.บ.โรงแรม หรือข้อบังคับนิติบุคคล ควรตรวจสอบก่อนเปิดขาย

## 5. แผนพัฒนา (Roadmap)

### Phase 1 — MVP ✅ (อยู่ใน repo นี้แล้ว)
- โครงการ + แผนที่, ห้อง + ผังรายชั้น + 3D อาคาร/ห้อง
- ผู้เช่า, การจอง (รายเดือน/รายวัน) พร้อมกันจองซ้ำ, สถานะมัดจำ
- จดมิเตอร์ด้วยรูป + OCR, ตรวจค่าที่น้อยกว่าครั้งก่อน
- ออกบิลรายเดือนอัตโนมัติ, QR PromptPay, บันทึกรับเงิน, พิมพ์บิล
- Dashboard: อัตราเข้าพัก รายรับ ค้างชำระ เงินมัดจำ เช็คอินที่ใกล้ถึง

### Phase 2 — พร้อมใช้งานจริง
- ระบบล็อกอินและสิทธิ์ (เจ้าของ / ผู้จัดการ / พนักงาน / ผู้เช่า), audit log
- **แอปเดสก์ท็อป Tauri** สำหรับ Mac/Windows + GitHub Actions build `.dmg` / `.msi`
- แจ้งเตือนและส่งบิลผ่าน LINE OA, ตรวจสลิปโอนเงินอัตโนมัติ
- ซิงก์ปฏิทิน iCal กับ Airbnb / Booking.com / Agoda (กันจองซ้ำข้ามแพลตฟอร์ม)
- สัญญาเช่า PDF + ลายเซ็นอิเล็กทรอนิกส์, ใบเสร็จ/ใบกำกับภาษี
- ค่าบริการอื่น ๆ (อินเทอร์เน็ต, ที่จอดรถ, ส่วนลด, ค่าปรับจ่ายช้า), ค่าน้ำขั้นต่ำ
- ย้ายไป PostgreSQL + backup อัตโนมัติ

### Phase 3 — ต่อยอด
- พอร์ทัลผู้เช่า: ดูบิล จ่ายเงิน แจ้งซ่อม จองพื้นที่ส่วนกลาง
- งานแม่บ้าน/ซ่อมบำรุง (ticket + รูปก่อน/หลัง)
- OCR ฝั่งเซิร์ฟเวอร์ด้วยโมเดลเฉพาะมิเตอร์ (ONNX ผ่าน crate `ort`) เพื่อความแม่นยำสูงขึ้น
- มิเตอร์อัจฉริยะ (IoT / Modbus / MQTT) อ่านค่าอัตโนมัติ
- 3D ขั้นสูง: นำเข้าโมเดล .glb หรือภาพ 360° ของห้องจริงสำหรับการตลาด
- รายงานกำไรขาดทุน, คาดการณ์อัตราเข้าพัก, ปรับราคารายวันตามฤดูกาล
